# AICAM 项目计划书

## 项目名称

基于 RV1126B 的边缘智能视频监控系统

## 一、项目定位

项目基于现有 `linux-v4l2-h264-streaming / camv3.5_hardenc` 视频链路，扩展端侧 AI 推理和部署能力，形成“视频采集 + 编码推流 + 本地检测 + 事件输出 + 指标统计”的完整边缘智能工程。

本项目定位为：

- 可在 RV1126B 板端稳定部署
- 可输出性能数据
- 可复现、可展示、可用于简历表述

## 二、项目目标

- 保留现有视频采集、编码、推流、播放能力
- 新增轻量检测模型的板端部署能力
- 实现视频推流与 AI 推理并行运行
- 输出检测框、类别、置信度与事件信息
- 统计推理耗时、推理 FPS、CPU、内存等指标

## 三、最终成果定义

项目完成后应至少具备以下能力：

- 摄像头视频采集正常
- H.264 视频流可正常推送和播放
- 板端可加载并运行 RKNN 模型
- 推理结果可输出为框、类别、置信度
- 检测事件可输出为日志和 JSONL
- 可统计推理耗时、编码 FPS、推理 FPS、CPU、内存
- 具备清晰的部署文档和启动流程

## 四、推荐技术路线

- 视频采集：`V4L2 + mmap`
- 视频编码：Rockchip `VENC`
- 视频输出：保留现有 `TCP -> epoll Gateway -> HTTP/H264`
- AI 推理：`RKNN Toolkit2 + RKNN Runtime`
- 模型选择：`YOLOv5n` 或 `YOLOv8n`
- 主程序语言：`C++`
- 转模脚本：`Python`
- 并发设计：采集线程 + 编码线程 + AI 线程 + 指标线程

## 五、总体架构

```text
Camera
  -> Capture(V4L2)
  -> Encode Queue -> Encode Thread -> Stream Output
  -> AI Queue -> AI Thread -> Preprocess -> RKNN Infer -> Postprocess -> Event Output
  -> Metrics Thread -> FPS / CPU / RSS / Throughput
```

## 六、模块划分

- `capture/`：帧结构与帧队列
- `encode/`：编码共享结构体
- `stream/`：长度前缀 TCP 推流客户端
- `ai/`：模型加载、预处理、推理、后处理
- `event/`：检测事件输出、日志、JSONL
- `metrics/`：耗时、FPS、CPU、内存统计
- `scripts/`：模型转换、启动、部署脚本
- `docs/`：部署说明、测试说明、结果记录

## 七、功能边界

### 本期必须做

- 单模型检测部署
- 单路视频输入
- 单路事件输出
- 板端性能统计
- 基础部署文档

### 本期不做

- 模型训练
- 多模型调度
- 多路摄像头
- Web 后台
- 云端联动
- 复杂 UI

## 八、实施阶段

### 阶段 1：固化视频链路基线

- 固定采集、编码、推流方案
- 明确输入分辨率、帧率、延迟基线
- 整理 README 与基线测试记录

### 阶段 2：模型选型与离线验证

- 选型 `YOLOv5n/YOLOv8n`
- 完成 ONNX -> RKNN 转换
- 板端跑通单图或单帧推理

### 阶段 3：板端推理模块开发

- 封装模型加载接口
- 完成预处理、推理、后处理
- 定义统一检测结果结构体

### 阶段 4：接入视频主链路

- 从采集线程抽帧给 AI 线程
- 保证 AI 不阻塞视频推流
- 支持每 N 帧推理一次

### 阶段 5：事件输出与性能统计

- 输出目标框、类别、置信度
- 生成 JSONL 事件记录
- 记录推理耗时、推理 FPS、CPU、内存

### 阶段 6：部署与文档收口

- 整理模型目录和板端依赖
- 提供启动脚本
- 补齐转换、部署、测试文档

## 九、验收指标

### 最低验收标准

- 视频流正常输出
- RKNN 模型在板端可稳定运行
- 视频与推理线程可并行
- 检测结果可输出
- 有完整部署流程说明

### 建议量化指标

- 推理持续运行 5 分钟以上
- 输出事件日志和 JSONL 记录
- 明确记录推理耗时、CPU、内存
- 给出 AI 接入前后的性能对比

## 十、风险与应对

- 风险：模型太重，板端跑不动
  应对：优先用 `YOLOv5n/YOLOv8n`，必要时降低输入尺寸或推理频率
- 风险：AI 推理拖慢视频流
  应对：独立线程、抽帧推理、限制 AI 队列深度
- 风险：模型输出格式不统一
  应对：优先导出更易部署的解码输出，并在 `ai/` 模块内集中处理差异
- 风险：项目展示价值不足
  应对：补齐部署、日志、性能、文档四件套
